# AidGap — project context for Claude Code

## What this is
AidGap compares humanitarian **need vs. funding** by crisis and ranks neglected crises.
Portfolio/resume project for Eli, a 2nd-year Data & Business Analytics student at IE University.
Goal: a full ongoing program (data pipeline + scoring model + dashboard + alerts), not a one-off report.

## Media (GDELT) decisions
- Framing: NARRATIVE ANALYSIS. We show who covers each crisis (outlet country mix), how much comes from state-linked outlets. We do NOT label articles "propaganda" (a headline statistic can't show that; needs case studies).
- "State-linked" = owned/funded/controlled by a government, list in `build_media_summary.py` (`STATE_LINKED`); short, so shares are a floor; ownership, not accuracy.
- GDELT FINDINGS (2026-11-17): requests with `timespan` longer than ~1 week return `{}` (use `1week`); 429 rate limits are heavy, short steady retries (15 s) work better than long backoff; `artlist` and `timelinevolraw` work at 1 week, `timelinetone` untested. Matching is loose (returned "Vietnam veteran..." for Viet Nam), so `build_media_summary.py` keeps only articles whose HEADLINE names the country (`TITLE_TERMS`), with exclusions.
- LANGUAGES (found by testing): GDELT machine-translates every article for matching, so ENGLISH keywords find Arabic/French/etc. articles; non-ASCII keywords are rejected ("illegal character"). `fetch_media.py` modes: `articles` (English, anywhere), `inland` (`sourcecountry:<FIPS>`, ANY language), `lang` (`sourcelang:<country's main language>`, `LANGS` map). Articles keep their `language`; titles are shown in the original script (`dir="auto"` for right-to-left) with a language tag, a language filter, and translate help: on-device browser Translator API if present, else a "Read translated page" Google Translate link. `title_en` is reserved for a stored build-time translation (options: Argos Translate offline, or an LLM API key).
- Title relevance filter: Latin names (`TITLE_TERMS`) plus native-script names (`TITLE_NATIVE`); GDELT also returns broken last characters, cleaned in `clean_title`.
- Sources REJECTED: Google News RSS (terms: personal feed-reader use only, not a public site). ReliefWeb API needs a pre-approved app name (free) = good next step for humanitarian reports per country.
- Status 2026-11-17: only 2-3 countries fetched so far (background job slow). Re-run `python src\fetch_media.py` (resumable) until done, then steps 9 and 6.
- Next: finish fetch, attention-vs-funding scatter (needs `volume` files), match CARE "Suffering in Silence", add local-language search, run fetch from GitHub Actions (different IP).

## Data source
- HDX HAPI **v2**: `https://hapi.humdata.org/api/v2/...` (funding: `coordination-context/funding`; needs: `affected-people/humanitarian-needs`)
- Every request needs `app_identifier`, stored in `src/config_local.py` (git-ignored — never commit or print it).
- Max 10,000 rows per request; page with `offset`.

## Data decisions (keep these)
- Funding: current year only; drop appeals with no `requirements_usd` (some records are dated 2031 with NaN targets).
- People in need: `population_status` INN, intersectoral sector, admin level 0; take the MAX across categories, never sum sectors.
- Countries without a PIN figure are mostly in **Regional response plans** (refugee-hosting countries, e.g. Latin America). Their per-country funding is unreliable → excluded from rankings (`has_national_plan` flag).
- CAUTION: `has_national_plan` really means "has a PIN figure" (from HAPI or hand-added), not "has a national plan".
- HAND-FOUND PIN RULE (`build_gap_table.py: add_manual_pin`, data in `data/reference/manual_pin.csv`): a hand figure is used only if HAPI has none AND `use_in_ranking = yes` (the figure belongs to the same plan as the FTS requirement and no source contradicts it badly). Used (all verified in their documents on 2026-11-17): Palestine 3.62M (high, OCHA PDF), Lebanon 1.4M (high, OCHA revised appeal), Madagascar 581K (medium, ECHO summary), Nepal 84,270 (LOW, UNICEF report, later 93,000 figure unresolved), Viet Nam 1.4M (medium), Cuba 4.2M (medium), Pakistan 2.8M (medium). NOT used: Honduras 2026 (unresolved).
- Rows with an older PIN year OR `pin_confidence = low` get `low_confidence = True` (still ranked, indicative only). Hand-added rows get a "hand-added figure" badge.
- Tied scores share a rank (e.g. Myanmar and Sudan both rank 8).
- Donors (`fetch_donors.py`): only money given to ONE country ("single" flows) is counted per donor; "shared" multi-country flows are reported separately (the API repeats them in full per country, which double-counted: Japan looked like top donor to Argentina). A country's own government spending is separated as `domestic` (Pakistan -> Pakistan was $441M). Totals include money outside the appeal, so they exceed appeal funding (Honduras: $147M of flows vs $1M appeal funding).
- Donation links: only pages that load (checked by `verify_links.py`). UNHCR pages failed to connect from here so none are listed. Not endorsements.

## Neglect Score v1
Percentile ranks among national-plan countries, weighted: coverage (% funded) 40%, $ per person in need 40%, scale (people in need) 20%. 0–100, higher = more neglected. Weights are a choice → later: sensitivity analysis.
